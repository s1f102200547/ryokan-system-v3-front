# NormalOperation（正常な使われ方）

このアプリが普段どう使われているかを、実世界の流れで書いたもの。ここから外れる使われ方を「異常」として、検知・拒否する対象にする（[Security.md](Security.md)）。

- 今は聞き取りで書いた仮の版。業務の操作の中身と回数は、ログを取って観察してから埋める
- 次の段階で、この流れをシステムの単位（どのリクエストが、どの順で、どれだけ届くか）に置き換える

## 1. 前提

| 項目 | 正常 |
|---|---|
| 使う人 | その日のシフトに入っているスタッフ2, 3名 |
| 場所 | 旅館のフロント |
| 回線 | 旅館の Wi-Fi |
| 端末 | 旅館の Windows PC（マルウェアに感染していない）。台数は3 |
| ブラウザ | 基本はChrome 1アカウントのみEdge |
| アカウント | PC 1台につき1つ。PC ごとに別のメールアドレスとパスワード |
| 入力 | メールアドレスとパスワードは、ブラウザのパスワードマネージャーの自動入力。手で打つことは基本的にない |
| 時間 | 6:00〜23:00 JST（この時間外はログインも画面も使えない。`src/constants/date.ts`） |

## 2. 前提を強制する方法

時間とアカウントはほぼ強制できている。回線・端末・ブラウザは、今は気付くだけ。これらの「まだ」は、ログイン API で IP・User-Agent を確かめることと、`requireSession` でセッションと IP・User-Agent の結び付けを確かめることの2か所で大半を賄える。

### 使う人

- 実装済み
  - 新規登録の無効（API からも無効であることを確認済み）
  - アカウントが PC 単位で、旅館の PC の外にアカウントがない
- まだ
  - SMS の MFA。SMS を受ける電話をフロントに置き、その場にいる人だけがログインできるようにする
  - 各 PC の Windows のサインインへの PIN の設定（旅館への依頼）
  - 人の区別はシステムではしない（方針。強制できるのはここまで）

### 場所

- 実装済み
  - なし（Slack のログイン通知の IP で気付くことだけはできる）
- まだ
  - SMS の MFA で、フロントの電話を持っている人に限る（「使う人」と同じ）
  - 場所そのものは、システムでは「回線」で代用する

### 回線

- 実装済み
  - ログインごとの IP の Slack への通知（気付くだけ）
- まだ
  - 許可する IP を環境変数に置き、それ以外からのログインをログイン API で断る
  - `requireSession` で、API の呼び出しごとに IP を確かめる
  - 客用と業務用の Wi-Fi を分ける（旅館側）。同じ回線だと、IP では客と区別できない

### 端末

- 実装済み
  - アカウントが PC 単位
  - Slack の通知への OS の表示
- まだ
  - User-Agent が Windows でなければ、ログイン API で断る
  - セッションを発行したときの IP・User-Agent に結び付け、違う組からの呼び出しを `requireSession` で 401 にする（盗まれた Cookie の対策も兼ねる）
  - Firebase のアカウントが3つだけであることの定期的な確認
  - 感染していないこと: Defender の有効化、自動更新、業務専用（旅館への依頼）

### ブラウザ

- 実装済み
  - Slack の通知へのブラウザの種類の表示
- まだ
  - アカウントごとに許可するブラウザを決め（Edge のアカウントは Edge だけ）、違えばログイン API で断る
  - API で `Sec-Fetch-Site: same-origin` がなければ断る（ブラウザ以外からの、Cookie を使った呼び出しを止める）

### アカウント

- 実装済み
  - 新規登録の無効
  - パスワードは openssl で生成し、アカウントごとに別
  - API ごとのセッションの検証（失効の確認を含む）
- まだ
  - 1アカウントにつきセッションは1つ。新しいログインで前のセッションを失効させる（ログインと同じ秒の失効は効かないという firebase-admin の仕様に注意して設計する）
  - 「端末」の結び付けで、アカウントと端末の組が違えば断る

### 入力

- 実装済み
  - パスワードは openssl で生成した値で、覚えられないので手で打てない
- まだ
  - パスワードマネージャーでの表示に、必ず Windows の認証を求める状態にする（「使う人」の PIN が前提）
  - ログインの失敗回数の制限（[Security.md](Security.md) §8 の未着手）
  - 自動入力かどうかは、システムでは確実には見分けられない（強制はここまで）

### 時間

- 実装済み
  - `proxy.ts` で、時間外の画面を `/time-restricted` に移す
  - 時間外のログインは 403
  - セッションは当日の 23:00 で切れる（22:55 以降のログインは Firebase の最低値の5分後まで）
  - `tests/time/` で、3つのタイムゾーンで検査している
- まだ
  - なし。観察で実際に使う時間帯が狭いと分かれば、そこに合わせて縮める
