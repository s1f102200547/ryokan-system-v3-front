# T6: 既知の脆弱性・悪性パッケージの悪用

脅威の説明と方針は `docs/Security/SecurityPolicy.md` の T6 を参照。

## 対策

| 順番 | 内容 |
|---|---|
| 1 | Cloud Run を**専用のサービスアカウント**（Firestore と Firebase Auth に必要な権限だけ）で動かす。被害の範囲を小さくする |
| 2 | Firestore Security Rules を**全拒否**にする。**本番は全拒否になっている（2026-11-01 確認）**。ルールはリポジトリの `firestore.rules` で管理し、`tests/emulator/firestoreRules.test.ts` で、Client SDK からはログインの有無にかかわらず `guestInfoV2`・`dailyInfo`・ほかのコレクションを読み書きできないことを確かめる（2026-11-02）。本番への反映は開発者が手で行う。サーバーは Admin SDK を使うので影響しない。E3 を塞ぎ、端末登録を回り込めないようにする前提でもある。ただしサービスアカウントには効かないので、Cloud Run が乗っ取られた場合の防御にはならない（T6-1 と T6-3 で対応する） |
| 3 | **Dependabot**（`npm`、`github-actions`、`docker`）を追加する。通常の更新は週1回・公開から7日待って `development` 宛てに PR を作る。セキュリティ更新の自動 PR は `main` 宛てにしか作れないので使わず、警告（alerts）だけを受け取る。警告が来たら `development` で直す。**悪用が報告された脆弱性は、数日以内に修正版をデプロイする**（7日を待たず、`npm install <pkg>@<修正版> --min-release-age=0` で手で上げる）。それ以外は週1回の PR で上げる |
| 4 | Node.js を 24 LTS に更新する（20 は 2026-04-30 にサポートが終了した） |
| 5 | `.npmrc` に `min-release-age=7`（npm 11.10 以降）を設定する。依存の install スクリプトは、`package.json` の `allowScripts` で全部 `false` にし、`.npmrc` の `strict-allow-scripts=true` で、書いていないものがあれば `npm ci` を失敗させる（`ignore-scripts=true` は黙って止めるので使わない。2026-11-02 決定） |
| 6 | GitHub Actions を**コミット SHA に固定**し、リポジトリ設定で SHA 固定を強制する（`pinact` で自動化できる）。CI で使うツール（`wait-on`、`firebase-tools`）もバージョンを固定する |
| 7 | CI の `permissions` を最小にする。全体は `contents: read` にし、`issues: write` は ZAP のジョブだけに付ける |
| 8 | deploy を **push で CI が成功したときだけ**（`workflow_run.event == 'push'`）にし、**CI が検査したコミット**（`head_sha`）をデプロイする |
| 9 | ZAP は対応不要と決めた指摘を rules ファイルで除外し、新しい指摘で CI を失敗させる |
| 10 | `.dockerignore` と `.gitignore` に `gha-creds-*.json` を追加する。`google-github-actions/auth` が作業ディレクトリに作る認証ファイルが、`COPY . .` で Docker build に入らないようにする（auth アクションの README の推奨）。build のステップを auth より前に動かす方法もある |
